What changed, and why

  • The path stopped being the subject. Destination is one line of proportional UI text in descriptionForeground, end-weighted to the last two segments, tooltip on hover and focus. Monospace returns only when [Edit] makes it editable.
  • Collision is amber and field-local. One line, resolved name in an inline chip, [Use name] to accept. The full path is not repeated — the Destination tail below already shows the resolved name. Nothing rewrites the input silently.
  • One omnibox, no tab bar. Refs, PRs and "create new branch" live in one list; a branch already checked out elsewhere is shown disabled with the owning directory as its badge instead of failing at submit.
  • Bring over is the point of the redesign: a summary with [Configure…], never a settings editor. Copy is default, link is the exception and carries writes to main. When nothing is configured the section still appears — silence is what ships a broken worktree.
  • Setup failure is not create failure. Screen 7 lives on the created worktree; no rollback, no red.
  • Removal is a report. Passed checks are shown so the warnings are legible; unproven checks render as ? and block; the typed confirmation appears only when something failed.

Pass 2 — provenance

  • The badge slot means one thing again. Every row's badge names the file that said so. writes to main and copied on Windows moved to an amber warning chip beside the row name, because they are consequences of the mode, not statements of origin. A linked row carries both.
  • Mixed provenance is click-to-expand. Collapsed, the badge counts sources (2 sources); expanded, each path names its own provider. Mixed is rare, so it costs the common case nothing — screen 16 draws single, collapsed and expanded together.
  • Excluded paths live in the expanded list, struck through and labelled excluded here — visible without opening a file, and legible as deliberate rather than as a failure. They are not counted in the row's total.
  • Ports name their numbers. The source file took back the badge slot; ASIMOV_PORT_APP=5183 now sits in the meta line, which is the only way the row pays off the port-collision finding.
  • Unreadable is its own state (19). The section names the file and what was lost, offers Open file, and leaves Create enabled. 19b puts malformed and empty side by side.
  • A losing provider gets one quiet row (18), inside the box, in the manner of the PR sign-in row. Switching rewrites extends in .vscode/worktree.json and never touches the other framework's file.

Pass 3 — four selections, and two corrections

  • A missing extends target is not an unreadable file. 19 now says the native file extends something that does not exist, and still lists what its own keys contribute, each badged .vscode/worktree.json. 19b is the genuinely unparseable file, where “nothing will be copied, linked or run” is true. 19c keeps malformed and empty side by side.
  • Occupied-branch modes are badges in the omnibox (23), resolved in the list before submit — reuse, reattach and adopt.
  • Base is refused, not ignored (22). Reuse, reattach and adopt each disable the Base line with the reason on the same row, so a ref that will not be applied never sits in the form looking as though it will.
  • The port preview is not a promise (7b). Ports are re-probed before .env.worktree is written, so a changed allocation is reported on the worktree row, naming only the variable that moved.

Pass 4 — two axes, and the removal contract

  • Branch mode and destination disposition are separate values. The omnibox resolves one of five modes (fresh, fresh-detached, reuse, reattach, adopt); debris is a property of the destination and composes with all of them (21, 21b). Recover left the omnibox because spending the branch badge on it made reuse-plus-debris undrawable.
  • Adopt and reattach are different states, so they are different screens. Reattach (20c) repairs a surviving entry with a stale path — one command, nothing lost. Adopt (20) reconstructs an entry git deleted, so it declares what the administrative directory took with it: staging decisions, sequencer state, ORIG_HEAD, per-worktree reflogs, the lock. Declared, never detected — a check that cannot fail is worse than a stated limitation.
  • A claimed branch is a hard refusal (20b). Reconstructing an entry by hand bypasses git's one-worktree-per-branch check and git says nothing, so the claim is verified before anything is written and the Adopt button is absent — only Create separate is offered.
  • Setup starts unchecked. A command a provider file supplied is not consent because a checkbox arrived pre-ticked. 4b's disabled Wait for setup is now the default state of a fresh dialog, not an unusual one.
  • An active agent is a refusal, not a confirmation (14). The report is still shown; the Remove button is absent. Screen 14b carries the typed confirmation, where every failure is a confirmable risk — dirty, untracked, locked, ignored content.
  • The branch-delete control is absent, not disabled, when the merge proof is false or unproven. A disabled control invites the trip to the terminal that the gate exists to prevent.
  • Panes are never killed (15). The line says the terminals were left running.
  • Ignored content gets its own row (13b), because git status says nothing about it and this dialog put most of it there. Three sentences: a count and a size, a could-not-be-sized under budget, or the provisioned material named.
  • A check has four outcomes (13c). Not-applicable is not unproven: unproven blocks, not-applicable carries no weight, and a detached-HEAD worktree has no merge to prove.
  • A stale offer re-prompts (24, 24b). The dialog holds a resolved snapshot; if the provider files or the removal assessment change underneath it, the new model is presented and the user submits again — including when the change made things safer.

Decisions to confirm

  • Destination label and value are on two lines, not one as in the brief's sketch. At 480px the label, Automatic badge, three icon buttons and a path tail cannot share a row without truncating the path to uselessness. Label row carries badge + actions; the path owns its own line.
  • Default destination stays …/.claude/worktrees/<name> (what your build does now), shown as …/anywhere-terminal/feat-search-2. Say the word if the sibling <repo>-<branch> default should come back.
  • Bring over rows are two lines (name + source badge, then the command/paths chip). The brief's three-column row does not survive 480px.
  • Merged sections summarize as 3 copied · 1 linked · 2 sources — counts first, provenance last. The excluded path stays out of that count and appears only in the expanded list \u2014 settled in pass 3.
  • Provenance labels are file paths, not framework names (asimov/worktree.yaml, not “asimov”). Longer, but it is the thing you open. Screen 17 shows .vscode/worktree.json owning Run setup because the native file overrode the inherited command.
  • Expansion state is per row and not remembered. Every dialog opens collapsed. If mixed provenance turns out to be common in your repos, always-expanded-when-mixed is the cheaper change.
  • Reattach and adopt both offer Create separate instead, in the collision line's Use name position — it falls back to a fresh worktree at a deduplicated path, and it is the only thing 20b offers.
  • Recover's checkbox and red Delete and create now sit under Destination, since debris is a destination state. Bring over is drawn on that screen: the cleared destination is provisioned like any fresh worktree.
  • Adopt is not offered for a directory with no git metadata (21b) — there is nothing to adopt, so that combination is refused rather than drawn.
  • Screen 14 keeps the full report above the refusal. The alternative is showing only the blocker, which hides the dirty state the user also needs to see before stopping the agent.
  • Occupied vs. Existing are two destination badges (amber, same treatment). If one word should cover both, Existing is the one to keep.
  • Base is hidden while Advanced is open — it would otherwise appear twice, since Base ref lives there too. Alternative: drop Base ref from Advanced entirely and keep only the compact line.
  • Not drawn: the "Create more" batch flow, issue-driven creation, remote hosts, and the [Configure…] editor itself — out of scope per the brief. Also not drawn: .vscode/tasks.json as the winning provider, which behaves like any other single source.
